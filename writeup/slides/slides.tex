\begin{frame}{What is an AST?}
	\begin{block}{Abstract Syntax Tree}
		An abstract syntax tree, or AST, is a tree-shaped representation of a program's execution structure after parsing.
	\end{block}

	\vspace{0.25cm}
	\begin{itemize}
		\item It removes surface-level syntax details such as whitespace and punctuation.
		\item It keeps the important structure of the program: variables, literals,
		      expressions, statements, and functions.
		\item Virtually every compiler reasons using ASTs.
	\end{itemize}

	\vspace{0.3cm}
	\centering
	\Large
	Source text $\rightarrow$ Parser $\rightarrow$ AST $\rightarrow$ Compiler optimization passes
\end{frame}

\begin{frame}{Why Use Haskell to Walk an AST and create another one?}
	\begin{itemize}
		\item Haskell's data types and pattern matching syntax make AST walking code very
		      intuitive.
		\item In other languages, The language syntax itself is represented by classes and
		      fields.
		\item In Haskell, the types are first class, so it is more natural to be able to
		      represent your AST nodes as types themselves than as classes and fields.
		\item Algebraic syntax is extremely useful for pattern matching and walking ASTs,
		      Given an AST is a discrete computer science tree, walking it using algebraic
		      syntax is very natural
		\item Types such as \texttt{Either} and \texttt{Maybe} make failed conversions,
		      unsupported syntax, and missing information visible in the function signatures.
	\end{itemize}
\end{frame}

\begin{frame}{What is MLIR?}
	\begin{itemize}
		\item MLIR is an intermediate representation used between high-level source code and
		      lower-level LLVM IR.
		\item It supports multiple levels of abstraction before reaching machine code.
	\end{itemize}

	\vspace{0.35cm}
	\centering
	\Large
	Source code $\rightarrow$ MLIR $\rightarrow$ LLVM IR $\rightarrow$ machine code
\end{frame}

% ------------------------------------------------------------
\begin{frame}[fragile]{MLIR Example}
	\begin{lstlisting}
module {
  func.func @add_example(%a: i32, %b: i32) -> i32 {
    %0 = arith.addi %a, %b : i32
    return %0 : i32
  }
}
  \end{lstlisting}

	\vspace{0.25cm}
	\begin{itemize}
		\item Note the syntax is in between high level and lowering - there are integers with
		      specific precision already defined for example.
		\item In general, there are much richer syntax across several dialects for linalg,
		      control flow, etc.
	\end{itemize}
\end{frame}

% ------------------------------------------------------------
\begin{frame}{Why MLIR?}
	\begin{itemize}
		\item Before code becomes machine code, it has to be broken into simpler operations,
		      types, blocks, and control flow.
		\item MLIR makes it easier to analyze, transform, and optimize programs in a standard
		      manner. (Think loop unrolling, dead code elimination, constant folding)
		\item Question: Why not just use ASTs? Answer: ASTs are closer to higher level source
		      code. MLIR and intermediate representations allow us to encode lower compiler
		      level and system level constructs.
	\end{itemize}

	\vspace{0.35cm}
	\centering
	\Large
	Python syntax $\rightarrow$ AST $\rightarrow$ MLIR $\rightarrow$ LLVM IR
\end{frame}
